## The core insight (why this is its own feature)

> "just asking a new domain to become as developed as idea.uk in one step is too much."

So the fleet needs a **maturity ladder**: a small number of named **rungs** a site climbs in
order, each a coherent, shippable increment, with **stepped reference examples** — a real
site (or template) demonstrating each rung — that the next site can *follow* rather than
having to reinvent the whole journey. A new domain starts at rung 1 and climbs; it never has
to become idea.uk-complete in a single build.

This reframes the portfolio problem from "make every site as good as idea.uk" (a cliff) into
"move every site up one rung at a time, against a worked example" (a staircase).

## What the separate thread should actually do (its brief)

Deliberation/design first, no build:

1. **Define the rungs.** Name the maturity levels from "onboarded/empty" → "fully useful"
   (idea.uk-class). Likely draws on existing shape: e.g. live content → nav-complete site →
   Tier-1 free probes → Tier-2 sticky utility → Tier-3 paid signature operation → full
   lifecycle pipeline. Ground each rung in what the platform can already produce.
2. **Pick the stepped reference examples.** For each rung, which real site best demonstrates
   it (the pilots + idea.uk are the obvious spine). A new site copies the *pattern* of the
   rung above it, not the whole of idea.uk.
3. **Define progression criteria + the promote step.** What makes a site "done" at rung N and
   ready for N+1 — measurable, and ideally checkable the way discovery checks already work.
4. **Sequence it against reality:** pilots → idea.uk full build → propagate. Respect the
   dependencies `013` already named (BIZ-014 entitlement flag / `client_entitlements` cache;
   claims-verification **V5** for any factual/legal tool content).
