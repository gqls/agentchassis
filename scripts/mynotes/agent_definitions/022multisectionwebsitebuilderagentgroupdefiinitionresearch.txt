# Workflow Configuration Locations

## Summary

You have TWO different types of workflow configurations:

### 1. **Agent Group Workflow** (Multi-Section Website Builder)
   - **Location**: `agent_group_definitions` table
   - **Field**: `orchestration_workflow` (JSONB)
   - **Group Type**: `multi-section-website-builder`
   - **What it does**: Defines how the GENERIC orchestrator spawns and coordinates multiple specialized agents
   - **File**: `/mnt/project/agent_group_definition_for_multi_section_website_builder`

   This workflow expects to spawn:
   - `content-creator-hero` (hero_writer role)
   - `content-creator-features` (features_writer role)
   - `content-creator-testimonials` (testimonials_writer role)
   - `content-creator-contact` (contact_writer role)
   - `content-creator-cta` (cta_writer role)

### 2. **Individual Agent Workflow** (Content Creator Hero)
   - **Location**: `agent_definitions` table
   - **Field**: `default_config.workflow` (JSONB nested in default_config)
   - **Agent Type**: `content-creator-hero`
   - **What it does**: Defines the INTERNAL workflow that the hero agent follows

   This workflow defines:
   ```json
   {
     "start_step": "spawn_researcher",
     "steps": {
       "spawn_researcher": {
         "action": "spawn_agent",
         "config": {
           "agent_type": "content-researcher",
           "role": "researcher"
         }
       },
       "call_researcher": {
         "action": "call_agent",
         "config": {
           "agent_type": "content-researcher",
           "target_role": "researcher"
         }
       },
       "generate_hero_content": {
         "action": "execute_llm_prompt",
         "config": {
           "input_fields": ["call_researcher"]
         }
       },
       "complete": {
         "action": "complete_workflow"
       }
     }
   }
   ```

## The Mismatch

### Current Working Flow:
1. User requests website → Generic orchestrator
2. Generic spawns only `content-creator-hero`
3. Hero agent runs its INTERNAL workflow:
   - Spawns `content-researcher`
   - Calls researcher for data
   - Generates hero content with research
   - Returns result

### Expected Multi-Section Flow (from agent_group_definitions):
1. User requests website → Generic orchestrator
2. Generic should spawn ALL agents:
   - `content-creator-hero`
   - `content-creator-features`
   - `content-creator-testimonials`
   - `content-creator-contact`
   - `content-creator-cta`
3. Each agent runs their own internal workflow
4. Generic aggregates all results

### agent_group_definitions table:
```sql
CREATE TABLE agent_group_definitions (
  id UUID PRIMARY KEY,
  name VARCHAR(255),
  group_type VARCHAR(100) UNIQUE,  -- e.g., 'multi-section-website-builder'
  agent_configs JSONB,              -- List of agent roles and types
  orchestration_workflow JSONB,     -- WORKFLOW DEFINED HERE
  version INTEGER,
  created_at TIMESTAMP,
  updated_at TIMESTAMP
);
```

### agent_definitions table:
```sql
CREATE TABLE agent_definitions (
  id UUID PRIMARY KEY,
  type VARCHAR(100) UNIQUE,         -- e.g., 'content-creator-hero'
  display_name VARCHAR(255),
  description TEXT,
  category VARCHAR(100),
  default_config JSONB,             -- Contains workflow nested inside
  capabilities JSONB,
  is_active BOOLEAN,
  image_repository VARCHAR(255),

  created_at TIMESTAMP,
  updated_at TIMESTAMP
);
```

  }
}

## The Question

**Which workflow is actually being used when you request a website?**

Based on the logs, it appears:
- The system is using the `agent_group_definitions` for the multi-section website builder
- But it's only spawning the hero agent
- The hero agent then uses its own internal workflow (from `agent_definitions`) to spawn the researcher

**The other agents (testimonials, CTA, etc.) are NOT being spawned.**

This suggests either:
1. The agent group workflow is not executing all its steps
2. The workflow execution is stopping after spawning just the hero agent
3. There's a different workflow being used than what's in the database

You should check:
1. What workflow the generic orchestrator is actually loading
2. Whether all the spawn steps in the agent_group_definitions are being executed
3. Why it stops after spawning only the hero agent
