We are building multi-page websites end to end from a domain name with agentchassis (Go actions, Postgres, Kafka agents; deploy git → GitHub Actions → Backblaze B2), and vonc.com / "Spark" — an AI daily-provocation site — is the live test bed. Its distinguishing mechanism is runtime-fill: some sections ship as deliberately empty shells marked data-runtime-fill, and loaders bundled into /assets/js/snippets.js fetch /data/provocations.json in the visitor's browser and populate them. That mechanism is now proven three times over: the daily provocation card, the six-room arena grid, and — as of 2026-07-08 — the Provocations Archive at /provocations/index.html, a page that had been planned since 22 June and silently failed to build ten times, because the planner emitted the page without sections and the build handler routes zero-sections to a step called complete_error that reports success. That page is now live and verified, so every primary call-to-action on the site finally resolves. The remaining task is small and specific: the index still shows the same idea twice — provocation-card renders a four-card "mini-lobby" directly above lobby-grid's six-card arena — and the agreed role split gives the arena to lobby-grid, and the single headline provocation, stats and CTAs to provocation-card. So the mini-lobby must go: the div.pc-card-grid block out of the component template, the data.lobby fill out of its loader, and the now-orphaned two-column media-query rule along with them. What makes this a question rather than an edit is that docs 003/002 state content_data is the source of truth and that patching rendered_html was explicitly rejected as an edit mechanism; that fix_component_template_action already ships a remove_element fix type which defers page-component content changes to a section-editor workflow; and that the rerender we habitually trigger only assembles pre-rendered components. A read-only bundle (/tmp/bundle_minilobby_trim.md) has been assembled to settle the supported path before anything is touched; its verdict determines the sequence, and the acceptance test is simply that the index still deploys six sections, provocation-card still fills, no .pc-card markup remains, lobby-grid is untouched, and the console is clean.
