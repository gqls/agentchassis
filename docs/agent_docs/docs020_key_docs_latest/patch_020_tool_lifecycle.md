# Patch for 020_tool_lifecycle.md

Context: two places in the doc describe `update_component_html`. Both
need small updates reflecting the April 2026 bug fixes:
1. The `version_note` → `change_description` column rename (the
   previous snapshot INSERT was silently failing for all calls)
2. The page_components UPDATE no longer overwrites `rendered_html`
   (that was corrupting per-page renders)

## Change 1 — tool-improver workflow description

Find this block (around line 131):

```markdown
5. **update_component** — `update_component_html` action saves the improved HTML. Optionally snapshots the previous version to `component_versions` first
6. **create_rerender_item** — creates a `needs_rerender` work item so the page gets rebuilt and deployed

**Go action:** `update_component_html` in `update_component_html_action.go`

The action also marks associated `page_components` as `build_status = 'pending'` so the rerender pipeline picks them up.
```

Replace with:

```markdown
5. **update_component** — `update_component_html` action saves the improved HTML. Optionally snapshots the previous version to `component_versions` first (best-effort: logged if it fails, doesn't block the update)
6. **create_rerender_item** — creates a `needs_rerender` work item so the page gets rebuilt and deployed

**Go action:** `update_component_html` in `update_component_html_action.go`

The action also marks associated `page_components` as `build_status = 'pending'` so the rerender pipeline picks them up. It does NOT overwrite `rendered_html` — the per-page render needs variable substitution and is regenerated by the rerender pipeline when it runs.

When the optional version snapshot is taken, the row in `component_versions` uses the live schema columns: `version_number` (computed as MAX+1 for this component), `change_description`, and `changed_by`. Prior to April 2026 this INSERT referenced a `version_note` column that had been renamed; the failure was invisible because the snapshot was best-effort. Any version history expected before that date is likely missing.
```

## Change 2 — actions table

Find this row (around line 292):

```markdown
| `update_component_html` | `update_component_html_action.go` | Update `html_template` with optional version snapshot |
```

Replace with:

```markdown
| `update_component_html` | `update_component_html_action.go` | Update `html_template` with optional version snapshot (to `component_versions` using `change_description` column); marks `page_components.build_status = 'pending'` without touching `rendered_html` |
```

## Rationale

Both updates add information that prevents mistakes rather than just
documenting what the code does:

- The "doesn't overwrite rendered_html" note prevents future writers
  from reintroducing the bug
- The "version history is likely missing pre-April 2026" note tells
  anyone doing forensics why the table is sparse for early rows
- The best-effort-logged clarification matches the code's actual
  behaviour (Warn log on snapshot failure, operation continues)
