How we automate this reasoning — the useful way to see it is that this whole conversation was a loop, and the loop has five moves, of which four automate cleanly and one is the crux:

Hypothesis from the report — "sections never reach save." A model reads the symptom and proposes a cause. Automatable: it's a prompt.
Gather evidence — analyse the repo, resolve targets, pull schema + runtime. Already automated — that's exactly what cmd/bundle does. This is the part you've built.
Test the hypothesis against evidence — the logs showed sections do reach save; the guard blocks them. The hypothesis was falsified. Automatable, and it's the heart of it.
Re-scope from what the evidence revealed — the bundle's code named spawn_content_writer, so the next bundle scopes there. Automatable: extract the named symbols from the in-scope code, make them the next scope.
Iterate — bundle 2, narrower, until the cause is pinned.

So the framework version is an agent loop around cmd/bundle: assemble → ask the model "what does this evidence confirm or refute, and what should the next bundle scope?" → re-assemble on the model's answer → repeat until it converges or gives up. The pieces all exist; the loop is the new part.
But here's the thing the conversation actually demonstrates, and it's why I'd be cautious. The single most valuable move in this entire debug was step 3 — the model saying "my hypothesis is wrong, the evidence contradicts it." Twice. The original "sections never reach save" framing was confidently wrong, and what saved it was checking the runtime evidence and abandoning the hypothesis. An automated loop that can't reliably do that doesn't debug — it confabulates a story that fits its first guess and scopes ever-deeper bundles chasing a phantom. LLMs are bad at this by default: they rationalise the initial hypothesis rather than falsify it. So the automation isn't hard because the plumbing is hard (the plumbing is cmd/bundle, done); it's hard because the reasoning quality that matters is the willingness to be wrong, and that's exactly what models do worst.
That points at how to build it safely, and it's the same shape as everything else this session:
Evidence-or-abstain, again. The loop's core prompt isn't "what's the bug?" — it's "what does this evidence confirm or refute, citing the specific log line or symbol; if it doesn't settle the hypothesis, say UNVERIFIABLE and name what evidence would." Identical contract to the doc-drift classifier. The model that can't cite isn't allowed to conclude — which forces the falsification step to be explicit rather than skipped.
Read-only and human-gated at the boundaries. The loop gathers (read-only, cmd/bundle) and proposes (a diagnosis + a suggested next scope). It does not apply fixes, and — the line from two sessions ago — it does not trigger runs to test hypotheses; it reads existing logs. The output is a diagnosis with its evidence trail, which a human acts on. The loop narrows the search; the person makes the call and writes the fix. Same division as classify-don't-merge.
Convergence guards, because a loop can run forever. Cap the iterations; require each new bundle to be narrower than the last (scope shrinking, not wandering); and if two iterations don't increase the evidence, stop and report "couldn't pin it, here's what I have" rather than spiralling. The recency-heuristic caution from the thinning tool, applied to reasoning depth.
So the concrete framework artefact is a cmd/diagnose (or an agent) that wraps cmd/bundle in that loop: hypothesis → bundle → cite-or-abstain → re-scope → repeat, capped, read-only, emitting an evidence-tagged diagnosis for a human. And — satisfyingly — it dogfoods everything: cmd/bundle is the gather, the analyser/code_symbols is the retrieval, and the cite-or-abstain contract is the doc-drift classifier's, reused. The thing you'd be automating is this exact session, with the human kept at the two points that mattered: deciding the fix, and being the backstop for the model's willingness to abandon a wrong hypothesis.
I haven't built it — it's a design direction, and the honest caveat is that the plumbing being ready doesn't make the reasoning reliable; the loop is only as good as the falsification discipline, and that wants real testing against known bugs (you have a growing set — this one, the silent-no-op catalogue in 016) before it's trusted to narrow scope on its own.
