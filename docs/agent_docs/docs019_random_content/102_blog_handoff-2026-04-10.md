## Discovered Mechanisms

### Unresolved status mechanism
Located in `load_work_item_actions.go` line ~893, in `insertWorkItem`:

1. Discovery check finds an issue, calls `insertWorkItem`
2. Action queries for terminal items (complete/failed) with same `item_key` in last 7 days
3. If newest terminal item < 3 hours old → suppress entirely (don't create)
4. If 2+ terminal items exist → create item with status `unresolved` and prefix summary with "[unresolved after N attempts]"
5. `unresolved` items are not dispatched — they sit visible for investigation

This correctly catches handlers that "succeed" without fixing the underlying issue. The `attempt_count = 0` is expected — these are new items born as `unresolved`, not retried items.

## Blog Listing Problem Summary (for reference)

### Problem 1: Slot name mismatch
`rebuild_blog_listing` always wrote to slot `blog-listing`. Some blog pages were planned with different section names (`article-grid`, `featured-article`, `category-section`). The action created a component that page assembly ignored.

### Problem 2: Template field name drift
The action loaded templates from `content_components` but the `blog-listing` component had empty `input_schema: {}` and was CSS-only (no `{{range}}` block, no article cards). 10KB of CSS rendered, zero articles appeared.

### Problem 3: Missing links in content-listing template
The `content-listing` component (which has the correct `input_schema`) renders article cards but `<h3>{{.title}}</h3>` has no `<a href>`. Articles aren't clickable.

### Problem 4: Empty shell sections
Blog pages planned with `featured-article`, `category-section`, `article-grid`, `content-sidebar` — four sections that were never filled. These render as blank 208-byte shells. This is an upstream planning problem — the planner shouldn't create sections it can't fill, or the content pipeline should fill them.
