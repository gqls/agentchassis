## Context

`bugs_open/285_HANDOFF_2026-08-15_section_list_assembly_is_lock_blind_…` (the OTHER 285, the shared-template one, already has its fix committed and awaits the roll — not this task).

**The defect, verified live this session.** `LoadPageSectionsFromSpecAction` (`platform/orchestration/actions/load_page_sections_from_spec_action.go`) is the one place the build pipeline assembles a page's section list (4 tiers: `site_plan_sections` → `site_specs.site_plan` → `pages.sections` → sibling synthesis). None of the four reads `page_components`. A human-LOCKED section that exists only on the live page can therefore never enter the list; downstream `save_page_sections` (DELETE-all-writable + INSERT-proposal) finds the locked row not in the proposal, exiles it to the tail and files a `lock_blocked_change … blocked_action=remove` item every pass. The 058 guard protects the ROW; nothing protects the LIST, and the `pages.sections` cache lies to every reader.

Live evidence (2026-08-15 ~19:00 BST): webdesign.uk `contact` (`pages.id 4ff10911-…`) `pages.sections = ["hero","contact-info"]`, three `page_components` rows incl. locked `chat-input-box` (row `7d3489c6-…`, `lock_type=permanent`, position 3, component `d6a8f57b-…` tool-level, active, all fields `static`). Fleet: 26 locked rows, **13 on tier-1 pages whose plan omits them** (contact + 12 loancalculator.co.uk tool pages); **6 open `remove` items, 5 filed TODAY 17:11–17:48Z** by `page-build-handler` runs on loancalculator (`spec_sections.source=site_plan_tables`, list `[hero, ported-prose, faq, tool-cta]`). So this is a fleet class firing now, not one site.

## Approach (candidate 1 of the bug file, made shared)

Make the assembled list = plan list ∪ the page's non-agent-writable live rows, using the guard's own predicate — at the single chokepoint, and give the one consumer that compares plan-vs-cache the same rule via a shared helper.

### Code changes

1. **`platform/orchestration/datahelpers/locked_page_sections.go` (new)**
   - `type LockedPageSlot { RowID, Slot string; Position int; ComponentID, ComponentFunction, ComponentName, LockType, LockedBy string }`
   - `LockedPageSlotsSQL` (exported const) — `SELECT … FROM page_components pc JOIN pages p ON p.id=pc.page_id LEFT JOIN content_components cc ON cc.id=pc.component_id WHERE p.site_id=$1 AND ($2='' OR p.name=$2) AND COALESCE(pc.build_status,'')<>'removed' AND NOT `+AgentWritableSQLFor("pc.")+` ORDER BY p.name, pc.position` — the lock predicate is the guard's, verbatim (`AgentWritableSQLFor`, `chrome_render_inputs.go:91`); the `removed` filter is a MEMBERSHIP condition (0 such rows today, measured), stated in the comment.
   - `LoadLockedPageSlots(ctx, db, siteID, pageName) ([]LockedPageSlot, error)` and `LoadLockedPageSlotsForSite(ctx, db, siteID) (map[string][]LockedPageSlot, error)`.
   - `MergeLockedPageSlots(list []string, locked []LockedPageSlot) (merged []string, inserted []LockedPageSlot, insertedAt []int)` — pure. Pairing mirrors `matchLockedRow` (`save_page_sections_action.go:1162`) with consume-once: per entry, arm 1 slot exact over all unconsumed rows, arm 2 kebab-normalised slot, arm 3 component function/name (the list has names, not ids — this stands in for the identity arm). Unpaired rows are inserted at `Position-1` clamped to `len(list)`, ascending position. Name = row `slot_name` (fallback component function).
   - Move `NormalizeComponentFunction` + `kebabCaseRe` from `actions/component_validation.go:78` into datahelpers; leave `actions.NormalizeComponentFunction` as a one-line delegate (same shape as `pageComponentAgentWritableSQL` → `datahelpers.AgentWritableSQLFor`, `lock_helpers.go:49`).

2. **`load_page_sections_from_spec_action.go`** — after tier assembly and only when a tier served (`len(specSections)>0`): load + merge; when tier 1 served insert `nil` into `specSectionFacts` at each `insertedAt` (keeps the `len==len` guard at L420 honest); replace the three per-tier syncs with ONE guarded sync after the merge: `UPDATE pages SET sections=$1::jsonb, updated_at=NOW() WHERE site_id=$2 AND name=$3 AND sections IS DISTINCT FROM $1::jsonb` (tier 3 now syncs too, a no-op unless the merge changed something). Result adds `locked_sections_merged` ([]string) and `locked_merge_count`. Query failure → Warn + proceed unmerged (mirrors `loadActiveLockedRows`; the row is still protected by the guard). Header comment rewritten: 5th source, why, the "no tier → no merge" rule and its reason (a locked-only list is neither plan nor page and would delete unlocked siblings).

3. **`discovery_checks/check_section_source_drift.go`** — load `LoadLockedPageSlotsForSite` once; compare `MergeLockedPageSlots(authoritative, locked[page])` vs `MergeLockedPageSlots(cache, locked[page])`. A locked live section can never register as drift by itself; a pre-fix cache (raw plan) does not either; real drift still flags. Header comment updated.
