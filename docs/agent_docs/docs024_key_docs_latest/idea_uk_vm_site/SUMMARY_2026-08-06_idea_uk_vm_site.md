# SUMMARY — idea.uk, 6 August 2026

**What we're trying to do.** idea.uk is a live, card-taking report tool. With
its front door rebuilt (see the 4 August summary — Cloudflare, strict TLS,
sealed origin), the work has moved up a layer: improve what the site actually
shows — logo, homepage, tools, news — with every change made by the platform's
own agents rather than by hand, and settle how the site can keep improving
without ever silently undoing a decision already made.

**Where we've come from.** The 4 August read-out ended with the infrastructure
done and the shop untouched. Since then the owner set a clear operating rule:
all fixes run through the framework. The first test of that rule found real
machinery — and real holes: a dispatch queue whose detected items never move
on their own, twelve poisoned work items that would each have deployed the
same wrong image, and a logo pipeline that silently fell back to a model that
cannot draw text.

**What we've done.** The logo now reads IDEA — bold rust capitals with a
lightbulb built into the A — generated by Google's image model ("banana"),
which the platform had wired all along; the old logo garbled because the
workflow never passed the routing field and quietly fell to a diffusion model.
The homepage now offers the free audience check beside the £29 report, each
labelled, either usable alone; the old standalone tools section is gone. That
removal took three attempts and taught a platform-wide lesson now on the
fleet's landmine list: a section marked "removed" resurrects on single-page
re-renders, and the "successful" deploy is an empty commit. News, never
configured for this site, is now set up and filling on its own cycle; tool
card images are being generated. All thirty-five component locks — every one
placed by earlier agent sessions, none by the owner — are removed at the
owner's instruction. And each change was recorded in the travelling docs so
the experience loop and future sessions can trace it.

**Where we are now.** The site is visibly better than a week ago and every
change on it is attributable. The one structural gap is the thing the locks
used to do badly: nothing now stops a future planner run from accidentally
rewriting a decision — the provenance notes exist, but the design agents do
not read them, and prose that nothing reads is not a control. The owner has
set the direction: decisions should allow change but forbid regression.

**Where we're going.** RFC 015 (filed today) proposes the mechanism: every
decision becomes one record with three faces — the why (prose), a steer
(injected into the generators' context, the way the palette pin already
works), and where checkable, an outcome guard (the checker layer files a
regression item if the decision stops being true of the served page). For
decisions that cannot be mechanically checked, a citation gate at the write
seams: any agent may change a decision-covered slot only by naming the
decision it supersedes — you may change what you can name, never what you
did not know existed. Steer and guards are data and config and can go live
incrementally; the citation gate is a shared-seam code change and goes to
architecture review and the council like any platform seam. Alongside that:
the owed follow-ons — card images wired into the tools pages, the favicon
and social card derived from the good logo, news verified once the feed
cycles, and the first genuine Stripe payment through the new front door.
