# SUMMARY — plumbing live, eyes built, two revisions owed (2026-08-03)

**What we're trying to do.** Give the estate two standing faculties: a vigilant senior
designer that continually improves every site from whole-site structure down to the finest
detail (bullet sizing, logo placement, how a graph sits beside the copy that cites it),
and an offer analyser — with benefit analysis inside it — that keeps asking whether each
site answers its target market's actual need in a way that profits us. Both built as
checkers and handlers, so improvement is the system's normal behaviour rather than a
person's intervention. The organising rule throughout: every detector ships with its
drain, because this platform's proven failure is correct findings nobody consumes — its
own audit predicted the owner's complaints three days early and died unread.

**Where we've come from.** The owner asked for roughly half of this on 24 July; it was
specified as four features and never built, deferred precisely because the improvement
loop was off and nothing drained the queue. Sites converge on one brochure skeleton for
measured, fixable reasons: the page planner is offered a brochure-shaped menu, the design
AI may only change colours, three shared header components serve all fourteen sites, and
five interactive components exist that no planner has ever picked. The offer side's raw
material — per-site monetisation analysis, audience definitions, a 43-proposition
positioning register — is written once at build time and read back by nothing. On
2 August the owner approved the full two-programme plan and made four calls: manual
per-site triggers for now (the always-on switch stays off); designer first; trial both
Gemini and Claude as the critic's eyes; broad autonomy, with two platform-honest
exceptions (shared chrome is forked per-site before editing; whole-site layout swaps
stay review items).

**What we've done.** Two config changes are applied and live: the improvement sweep's
producer now points at the scheduler lane (still switched off — that flip stays the
owner's), and the dishonest audit cap is gone — the loop audits when a site actually
changed or a fortnight has passed, promotes findings to workers on every path including
the paths that used to skip it, and when three audits at an unchanged site produce fixes
that never land it says so on the roadmap instead of reporting "clean". Three code pieces
are written, tested and committed, dormant until the next image ships: the writer that
turns browser measurements (unreadable contrast, broken images) into routed work items;
whole-site screenshot capture, phone and desktop, on the existing render sweep; and the
vision seam — both Gemini and Claude can now be sent those screenshots, so the model
trial is one config key. Along the way three of the plan's own premises failed
verification and were corrected before they shipped, including a "dead topic" claim
inherited from another lane that turned out to be the chassis's main request lane.

**Where we are now.** The review council has ruled on all three code submissions: the
screenshot capture was approved first time, and its one substantive catch — capture
failures were logged but not counted, so the future critic could silently judge half a
site — is already fixed and committed. The other two came back REVISE overnight, each
with one gating objection (the findings-writer and the vision seam); the objections have
not yet been read and acted on, and by this platform's rules the code is already on the
shared branch, so answering them is the first job of the next session, before the image
rolls. Nothing new is enabled anywhere: every change is either live-but-inert config,
or committed code no workflow names yet. One proof is owed and deliberately parked: a
witnessed run of the improvement loop through the new gate, which is also what closes
the audit-cap bug.

**Where we're going.** Next: read and answer the two REVISE objections, roll the chassis
and browser-runner images (pod-verified), wire the render audit's write step, then prove
the whole spine on one specimen site — a browser measurement travelling to a changed
page with no human in the middle. Then the critic itself: screenshots in, concrete
routed findings out, the Gemini-versus-Claude comparison recorded as a ruling. Behind
it in order: the page-recompose handler that finally gives structure findings a
consumer, the revived brief-fidelity audit (its acceptance test is the platform's own
three-day-early finding, taken through to a changed page), the anti-brochure planner
constraints, and — on the same rails, second as ruled — the offer and benefit analyser.
