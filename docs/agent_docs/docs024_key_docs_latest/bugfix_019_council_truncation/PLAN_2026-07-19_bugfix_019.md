# PLAN — bugs_open/019: a truncated reviewer must not void the council round

Started 2026-07-19, session "bugfix 019". Evidence and missteps in
[`NOTES_bugfix_019.md`](NOTES_bugfix_019.md); the case file is
`/bugs_open/019_HANDOFF_2026-07-18_one_truncated_reviewer_voids_whole_council_round.md`.

## The corrected problem statement

The case file's §"Root cause" names `diagnose_council_decide_action.go`'s
`json.Valid` asymmetry. Measured over 10 days, that path accounts for **2** voided
runs; **9** died upstream at `execute_llm_prompt` and never reached it. The
dominant chain is:

```
anthropic.go:180   stop_reason==max_tokens  ->  return "", error   (partial DISCARDED)
ai_actions.go      falls through to "unhandled error"  ->  step fails
coordinator.go     routeToErrorStep -> error_step
council-gate cfg   every review_* step: error_step = complete_invalid
                   seats are SEQUENTIAL, review_editquality is first
                   => seat 1 overruns -> whole round terminal, zero verdicts
```

So the defect is not "the decider mishandles a bad review". It is **"a seat that
overruns its cap aborts the round before the other seats run"**, and the decider
bug is a second, rarer instance of the same idea.

## Design constraints

1. **Preserve the safety property.** The hard error exists for a real reason,
   stated in the file's own header comment: *a council that cannot read its
   reviewers must not wave a plan through.* Any fix must keep an unreadable seat
   from turning into a silent approval.
2. **A readable objection stays decisive.** An unreadable seat must never
   overturn a `object`/`veto` from a seat that was read.
3. **Config changes are hazardous here.** The re-seed clobber landmine
   (patch-style seeds) and the 099 roster-mirror requirement mean a fix living
   mostly in per-seat config will drift across three councils × 13 seats.
   Prefer Go.
4. **Don't quietly raise the shared cap.** Two threads independently declined
   this for the same reason (config-clobber during an unrelated task). The
   raise-vs-void decision is explicitly open and is not this fix's to take
   unilaterally — and on the file's own measurements raising it *moves* the
   cliff rather than removing it.

## Options considered for "let the round continue"

| # | Option | Verdict |
|---|---|---|
| A | Point each seat's `error_step` at the next gate instead of `complete_invalid` | **Rejected.** Pure config, no Go — but it swallows *genuine* errors (API down, bad model) into a silent skip, loses the truncation marker, and needs editing 13 seats × 3 councils plus the 099 mirror. Trades one silent failure for a worse one. |
| B | Retry the seat once at a higher cap with a "be terse" instruction | **Not on its own.** Addresses the seat's review actually being wanted, but costs a second call on the slowest path, and still needs a fallback when the retry also overruns. Possible later refinement, not the fix. |
| C | Raise `max_tokens` to ~12–16k | **Rejected as a fix** (see constraint 4). Moves the cliff. Legitimate as a *separate* owner decision. |
| D | Return the partial, let the step tolerate it, salvage the verdict downstream | **Chosen.** See below. |

## Chosen shape — three layers, rooted at the real site

**Layer 1 — `platform/aiservice/anthropic.go`: stop destroying the evidence.**
Return the partial text *alongside* a typed truncation error instead of `""`.
Additive and safe: every existing caller does `if err != nil { … }` and is
unaffected; only a caller that explicitly inspects the type can salvage. This is
the root fix — the platform currently detects truncation correctly and then
throws away the only thing that would let anything recover from it. (It also
makes the case file's fix-candidate 2 *possible*; today it is not, because the
bytes never leave this function.)

**Layer 2 — `platform/orchestration/actions/ai_actions.go`: tolerate, don't abort.**
On a truncation error where the step opts in, record the partial plus an explicit
`__truncated` marker as the step's result so the step **succeeds** and the chain
continues to the next seat. This is the layer that removes the class: without it,
seat 1 still aborts everything, and every downstream cleverness is unreachable.

**Layer 3 — `diagnose_council_decide_action.go`: loud abstention, never a silent approve.**
Repair/parse the partial (`repairTruncatedJSON` already exists at
`apply_adoption_plan_action.go:950`; `councilReview` puts `reviewer` and `verdict`
first, so a truncated review usually retains both). If a verdict is recoverable,
use it and mark the review degraded. If not, count the seat as `unreadable` —
tracked *separately* from relevance-filter `abstained` — surface it in the
decision object and the council report, and **downgrade an otherwise-`approve`
outcome to `revise` whenever any seat was unreadable.** Constraint 2 falls out of
this for free: a readable objection already produces `revise` or stronger.

Layers 1+2 stop the round being lost. Layer 3 is what keeps the fix honest.
