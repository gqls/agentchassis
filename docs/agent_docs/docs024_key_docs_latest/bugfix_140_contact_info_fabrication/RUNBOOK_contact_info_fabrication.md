## R1 — Is a bug actually unowned? (do NOT trust `who-owns.py` alone)

`scripts/who-owns.py` reads COMMITS, so filing a bug makes it look owned. It said
"OWNED or recently active" for eight consecutive candidates, all of them idle.


files at once takes seconds.

session's history contains the `bugs_open/` DIRECTORY LISTING, so every number
matches every session that ever ran `ls`. The tell: `bugs_open/072` scores ~290
across sessions with no connection to it, because it is in the SessionStart
landmine hook text injected fleet-wide. **Score recent context, not whole files.**

## R6 — Verify the regexes you add to a discovery check ACTUALLY match

A Postgres regex that does not compile the way you think is a silent no-op: the
check returns zero findings and looks healthy.

```sql
SELECT count(*) FILTER (WHERE rendered_html ~* '\+?1[- ]?\(?234\)?[- ]?567[- ]?890')            AS dummy_phone,
       count(*) FILTER (WHERE rendered_html ~* 'Monday\s*[-–—]\s*Friday,?\s*9am\s*[-–—]\s*6pm') AS fab_hours,
       count(*) FILTER (WHERE rendered_html ~* 'Tuesday\s*[-–—]\s*Friday,?\s*3am\s*[-–—]\s*4pm') AS neg_control
FROM page_components WHERE rendered_html IS NOT NULL AND locked_at IS NULL;
```

**Always include the negative control.** A pattern that matches everything and a
pattern that matches the right thing look identical from the positive count
alone. Measured 2026-08-02: 1 / 8 / **0**.

Also assert `matched_text` extracts rather than returning NULL — the `CASE` and
the `SUBSTRING` are two separate expressions and it is easy to update one:

```sql
SELECT substring(rendered_html from '(?i)((?:…your alternation…))') FROM page_components
 WHERE rendered_html ~* 'Monday\s*[-–—]\s*Friday' LIMIT 2;
```
