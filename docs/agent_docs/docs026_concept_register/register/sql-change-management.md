### SQLC-001 — SQL needle-gate surgery pattern (guarded, idempotent, reversible DB edits)
- **status:** convention
- **status-evidence:** Practised in every w1–w9/slice4a file in its source unit; codified as "the needle-gate rule REFINED in 016b_7 (count expectations mechanically from the dump; mismatch = drift OR bad expectation)"; extended explicitly to documentation edits ("needle discipline applies to docs too").

- **what:** The dominant change-management method for production data edits (templates, layouts, prompts, and even docs): dump the current bytes; derive byte-exact needles per element (multi-line `E'…\n…'` needles to disambiguate repeated strings; `position()` where a needle contains a literal `%`); run a read-only GATE query asserting each needle's presence plus mechanically-derived occurrence counts; apply nested exact-string `replace()` (or `\1`-anchored `regexp_replace`) UPDATEs guarded on a pre-state marker so re-runs are 0-row no-ops; check RETURNING booleans as immediate post-conditions; ship separate verify and inverse-rollback files plus a full .bak dump before every mutation. The 019 migrations extend this same pattern to agent prompts specifically: sentinel-guarded idempotency, abort-if-fragments-moved checks, and a paired down-migration. Sibling rules: `\set ON_ERROR_STOP on` for any file of dependent mutations; always run SQL as files, never pasted into interactive psql.
