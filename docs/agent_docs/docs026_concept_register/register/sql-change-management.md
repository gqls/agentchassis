### SQLC-001 — SQL needle-gate surgery pattern (guarded, idempotent, reversible DB edits)
- **status:** convention
- **status-evidence:** Practised in every w1–w9/slice4a file in its source unit; codified as "the needle-gate rule REFINED in 016b_7 (count expectations mechanically from the dump; mismatch = drift OR bad expectation)"; extended explicitly to documentation edits ("needle discipline applies to docs too").
- **stage2-verified (2026-07-14):** deployed → convention — This is a change-management methodology/pattern (needle-gate SQL editing), not a single built artifact; not a plan-in-present-tense false positive — cited source files w2_01_footer_fix.sql, w3b_01_hero_conversion.sql, 019_pcw_prompt_item_fields.sql all exist under docs024_key_docs_latest/, confirming the practice is...
- **what:** The dominant change-management method for production data edits (templates, layouts, prompts, and even docs): dump the current bytes; derive byte-exact needles per element (multi-line `E'…\n…'` needles to disambiguate repeated strings; `position()` where a needle contains a literal `%`); run a read-only GATE query asserting each needle's presence plus mechanically-derived occurrence counts; apply nested exact-string `replace()` (or `\1`-anchored `regexp_replace`) UPDATEs guarded on a pre-state marker so re-runs are 0-row no-ops; check RETURNING booleans as immediate post-conditions; ship separate verify and inverse-rollback files plus a full .bak dump before every mutation. The 019 migrations extend this same pattern to agent prompts specifically: sentinel-guarded idempotency, abort-if-fragments-moved checks, and a paired down-migration. Sibling rules: `\set ON_ERROR_STOP on` for any file of dependent mutations; always run SQL as files, never pasted into interactive psql.
- **sources:** w2_01_footer_fix.sql; w3b_01_hero_conversion.sql; slice4a_creator_prompt.sql; 019_pcw_prompt_item_fields.sql; running_notes_scheme_to_components(55).md#Sp,#Sv,#Ss (idea_uk_section_data unit)
- **relations:** register/debugging.md DBG-016 (SQL/DB template-and-data surgery method — the same method extracted independently under the debugging category); agent re-seed risk; documentation-system needle discipline on docs
- **verify-later:** 016b guide's needle-gate entries; whether this pattern is written up anywhere as a standing convention doc

### SQLC-002 — `platform/livespec`: the declaration of a live DB object, in a file that is ALLOWED to change
- **status:** **phase 1 LIVE 2026-08-22** (four Go guards read it; council `b3676918` APPROVED at round 2, commit `873575ecf`). **Phase 2 BUILT and proven against the live DB the same day, but NOT DEPLOYED** — `config-key-audit --live-declaration-drift [--report]` + a check image + a CronJob at 07:00 UTC; the image is unbuilt/unpushed and the CronJob unapplied, so nothing runs on a schedule until the owner's next `make release`. ⚠ The council gate **REFUSED** phase 2 as out of scope (all `cmd/`/`build/`/`deployments/`/`makefile`), which is true of every check service in this family.
- **what:** A leaf Go package holding, per guarded live database object, its identity, the SQL that reads it (`ProbeSQL`), and what its text must and must not contain. Kinds as of 2026-08-22: `scheduled_task` (a `pre_query`), `trigger_fn` (a `pg_get_functiondef` body) and `trigger_bindings` (a `pg_trigger` count). It exists because migrations are **append-only history** — `schema_migrations` records a checksum of the FILE, so an applied migration must never be edited — while the live object is the accumulation of every migration since. A guard that reads a migration is therefore pinned to a frozen snapshot **by construction**: `TestDivergenceVocabularyMatchesMigration357` used to fail with *"migration 357 no longer contains X"*, an event the checksum rule has already made impossible. Two further guards called `t.Skipf` on a read error, so a rename was a silent green. Measured 2026-08-22: the claim-timeout exclusion clause was amended by migrations **322, 331 and 374** under filenames the old guard's glob could not match, and migration **220 was edited nine times after it applied** — for most of its life it *was* the mutable declaration, and when the checksum convention froze that role nothing replaced it, which is why `482` ended up spelling its declaration into a **prose comment** for a test to parse.
- **⚠ keyed on the OBJECT, never the migration.** Migration `506` writes **two** live objects (a `scheduled_tasks` row and an `agent_definitions` query) and its guard checked only the first — a registry keyed on files would reproduce the defect inside the fix.
- **⚠ inert entries are COUNTED.** `DeferredDeclarations` is asserted by a test, so a declaration nothing can check yet cannot quietly read as guarded. One entry is inert today: the trigger **binding count**, which is the only thing that can catch the live trigger SET outgrowing its migration — as it already has (357 declares two bindings; `552` added a third; **3** measured live as of 2026-08-22).
- **⚠ the live object can misdescribe ITSELF.** The live `scheduled_tasks.pre_query` for `claimed-item-timeout` still states the contract is *"the LOCKSTEP TWIN of the `RegisterVerifier()` calls"* and names `TestRegisteredVerifiersMatchClaimTimeoutExclusion`. Both were superseded on 2026-08-19 (migration `482` made it the union of BOTH gate rosters) and that test no longer exists. **That sentence is the original cause of `bugs_closed/317`**, and reading the live row — the correct instinct — still hands it to you. A text-vs-clause auditor would pass this: the clause matches, the prose lies.
- **regrowth guard:** `TestNoNewMigrationFileReadersOutsideTheAllowList` scans **AST string literals, never comments** (a source-scanning test that reads comments makes comments load-bearing), and requires both a `sql_for_agents` literal and a read call. Its allow-list is **5** files as of 2026-08-22, each carrying a written reason; the 4 guards converted by this change are deliberately absent. Verified empirically: it fired on exactly those 4 before conversion and passes after.
- **sources:** `platform/livespec/livespec.go`, `platform/livespec/livespec_test.go`; the four converted guards (`claim_timeout_exclusion_lockstep_test.go`, `complete_work_item_retry_guard_test.go`, `page_component_divergence_test.go`, `site_component_divergence_test.go`); `bugs_open/363`; `docs/agent_docs/docs024_key_docs_latest/live_object_declaration_drift/`
