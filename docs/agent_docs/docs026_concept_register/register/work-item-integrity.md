### WII-003 — complete_work_item flag-preservation guard (Fix A)
- **status:** deployed
- **status-evidence:** "Fix A marked applied" in the FOCUS doc; listed in the deploy batch ("Fix A must ship with S2").
- **what:** `CompleteWorkItemAction` did an unconditional UPDATE to status='complete', so the dispatch loop's mark_complete clobbered deliberate handler-set flags (needs_human_review from mark_needs_review / mark_no_sections). ### WII-005 — Work-item dedup index + two-strike anti-churn rule
- **status:** deployed
- **status-evidence:** running_notes_15(12) Part 8: "Key enabling discovery (insertWorkItem …): a built-in two-strike rule."
- **what:** `idx_swi_dedup` is a partial UNIQUE(site_id,item_key) over non-terminal statuses only — terminal rows are excluded so a completed key can be requeued cleanly; ON CONFLICT DO NOTHING is the safe insert idiom. `insertWorkItem` adds a two-strike rule (an item_key with ≥2 terminal attempts in 7 days inserts as `unresolved`; <3h after a terminal item is suppressed), so discovery checks need no anti-churn logic of their own. A non-terminal flag (needs_human_review) deliberately holds the dedup slot, preventing re-trigger loops. Same rule as the work-dispatch register's WDS-007, described here from the dedup-index angle.
- **sources:** running_notes_15(12).md#part-8; HANDOFF_page_pipeline(11).md#schema-gotchas; RUNBOOK_linking_phantom_fixes(7).md#5

- **verify-later:** insertWorkItem two-strike logic; idx_swi_dedup definition

### WII-008 — `mistyped_deployed_page`: a create arm that REFUSES a live-page collision and routes the decision to a human
- **status:** deployed — **LIVE on chassis v1.0.1225**, pod-verified on both replicas with a positive control in the same exec (2026-08-01). Council `ccd4384c-aff9-45ed-80b2-01c3ced573bb` **APPROVED at round 2**. `bugs_closed/081`.
- **status-evidence:** committed on `apply_gap_plan_action.go`; four tests pass (`go test ./platform/orchestration/actions/ -run TestApplyNewPage`), one firing branch and three controls. No production run — the live induction is scripted and owed (`bugfix_081_deployed_mistyped_page/RUNBOOK`).
- **what:** `applyNewPage` (content-gap-planner's `new_page` approach) used to end in `ON CONFLICT (site_id, name) DO UPDATE SET title, sections` — a CREATE arm that silently became a PARTIAL update, applying the plan's content while leaving `page_type` at the existing row's value. On a **deployed** page that overwrote live content with a plan written for a different role AND left the mistype in place, so the originating check re-raised for ever (measured: 2026-05-01 → 2026-07-31 on ai-agent-orchestration.com). The arm now uses `DO NOTHING ... RETURNING id` and hands a collision to `resolveNewPageConflict`, which does the whole read-decide-write in **ONE transaction with `SELECT ... FOR UPDATE`** — the column races the publish sweep, so unlocked it could read a page mid-deploy as not-yet-deployed and overwrite it as it went live. On `build_status='deployed'` with a differing `page_type` it **mutates nothing**: it files a **new item type `mistyped_deployed_page`** at `needs_human_review` (spec carries `existing_type`, `wanted_type` and the exact remediation SQL) and sets the originating item to `blocked` with a message naming the conflict — deliberately not `complete`, per WII-001.
- **the item is filed through `insertWorkItem`, NOT hand-rolled, and that was the council's gating objection (round 1 REVISE, `guidelines` HIGH; also `improvement_guardian`, `guardian`, `reuse_agent`).** A bare `ON CONFLICT DO NOTHING` does not match `idx_swi_dedup`'s partial predicate over non-terminal statuses (WII-005) and carries neither the two-strike rule nor `recurrenceExpected` — so the advertised dedup was not guaranteed. `recurrenceExpected` is left **false** deliberately: this is a detected defect, not an action request, so a recurrence after a human resolution genuinely is a second strike. `handlerAgent` is empty by design, and measured safe — `claim_work_item_action.go:102` and `load_work_item_actions.go:632` both claim `status IN ('triaged','approved')`, so a `needs_human_review` row cannot be picked up.
- **⚠ the tests that guard this had to be rebuilt, because the first set was VACUOUS.** `mock.ExpectationsWereMet()` was used to assert "no `UPDATE pages` happened"; it reports registrations made and not consumed and never sees an EXTRA call, and the code discarded the `Exec` error so sqlmock's complaint went nowhere. Induced: the mutation PASSED. What carries the negative assertion is the production code **checking and propagating every statement's error** — re-induced after the rewrite, the same edit FAILS. See `LANDMINES.md` "`mock.ExpectationsWereMet()` is NOT 'no database call happened'". Result now reports `page_created` so a caller can tell a created page from a refreshed one (the `item_created` treatment of `bugs_open/091`, one field over). **Another workstream needs to know this type exists**: it has no handler agent by design, it holds a dedup slot at a non-terminal status (WII-005), and it is a *decision* queue, not a work queue — anything draining `needs_human_review` (`bugs_open/033`) will meet it.
- **why refuse rather than re-type:** `bugs_open/081` established that no predicate distinguishes a real news listing from a catalog index that embeds one — on robot-hands.com both carry `sections=["news-listing"]` byte-identically, and a third page of the same shape is archived. Guessing risks re-typing a working page, which is worse than the loop. The planner has already named the page, so the refusal needs no discriminator: it only has to notice the name is taken by a page holding a different role.
- **scope, and the number that set it:** guard covers `deployed` rows only. Live query 2026-07-31 — mistyped pages by build_status: **deployed 5, needs_rebuild 0, planned 0**. Extending the re-type to never-shipped rows would repair nothing extant while widening a generic arm's authority; declined on that count and pinned by `TestApplyNewPage_UndeployedTypeConflictStillRefreshes`.
- **sources:** bugs_closed/081_HANDOFF_2026-07-26_deployed_but_mistyped_page_has_no_repair_path.md; docs024_key_docs_latest/bugfix_081_deployed_mistyped_page/{PLAN,RUNBOOK,NOTES}; 016b §9 "An `ON CONFLICT DO UPDATE` that names SOME columns turns a CREATE into a silent PARTIAL update"
- **the class is NOT closed:** four sibling `pages` upserts share the identical omission and a fifth carries the opposite risk (re-types on conflict) — censused in `bugs_open/175` at the `bug_historian` seat's request, deliberately not fixed in this bug patch.
- **relations:** silent-completion failure family (WII-001 — `blocked` not `complete` is that doctrine applied); dedup index + non-terminal slot (WII-005); routing map (WII-006 — this type deliberately has NO handler); `bugs_closed/015` retype_existing, whose `build_status <> 'deployed'` exclusion left this population unowned; `bugs_open/091` (the reporting half, same file); `bugs_open/033` (the human-review queue this files into); `bugs_open/098` (same "two correct guards, unowned intersection" shape).
