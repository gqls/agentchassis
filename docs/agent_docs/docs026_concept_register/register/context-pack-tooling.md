### CTXP-001 — Context-pack code-gathering tooling: analyser/assembler vs package_*.sh (a dropped trade-off discussion)
- **status:** superseded
- **status-evidence:** The archived `GUIDE_deploy_from_context_packs(1).md` (adoption/docubundle) devotes half its length to a considered trade-off between the directory-walking `package_page_build_debug.sh` script ("broad, thorough, large... 110 files when the task really turns on about 14... caught registry.go") and the call-graph-based `analyser.go`/`assembler.go` pair ("leaner... but currently blind to wiring files" like registry.go, because registration happens via init, not calls). The LIVE rewritten guide (`docubundle/GUIDE_deploy_from_context_packs.md`) drops this discussion entirely — it restructures around the deploy-mechanism reference (A–F) and a per-project quick reference, never mentioning the analyser/assembler tool or its registry.go blind spot at all.
- **what:** Two competing tools for assembling an LLM chat's working context from a Go repo: (1) `package_*.sh`, concatenating whole hand-picked directories plus a live DB/pod capture into one text bundle — the family catalogued in CTXP-002; (2) `analyser.go` + `assembler.go`, pulling only named functions plus their call-graph neighbourhood into a tight bundle from a `-scope`/`-task`/`-constitution` spec — the tool catalogued in register/context-assembly.md CTXA-010 and register/contextkit-toolchain.md. The archived guide flags that the assembler's call-graph approach misses non-call wiring (init()-based registry.go registration) that the script's brute-force directory walk happens to catch. The tool itself survives with a proper home under contextkit; what was dropped from the doc lineage is the discussion of WHEN to reach for it over the script.

### CTXP-002 — Docubundle / package_*.sh context-packaging practice (module packager + dbcontext + deploy guide)
- **status:** deployed
- **status-evidence:** Working scripts and generated context files present across at least three workstreams: `package_page_build_debug.sh` + 1.6MB output_contexts (adoption); `package_thunder_checkpoint_race.sh` + a 633KB generated production context file (finetuning); `package_content_quality_debug.sh` + filled-in 001_context invocations (content-quality/idea.uk). GUIDE_deploy_from_context_packs documents the operating loop across four live packs.
- **what:** A repeated pattern across independent workstreams (adoption, finetuning, content-quality) rather than a single tool: a self-contained `package_<subject>_debug.sh` packager script that bundles a subsystem's blast-radius (the relevant code slice, reuse-discovery catalogue layers — registry.go, datahelpers, input_contracts — and the working docs) plus an OPTIONAL read-only live capture (schema, decisive queries, agent-def workflows, runtime state) into one context file, to seed a fresh AI-assistant thread on a specific blocker. Paired with hand-written `CONTEXT_PACK_*` / `NEXT_CHAT_MANIFEST` docs stating the blocker, the verified root cause, the applied fix, and next actions — and, where the working set is still too large, a targeted extract file ("use the targeted extract, not the 72k-line file") showing deliberate context-size curation. The companion `dbcontext` Go CLI shells out to a configurable `psql` for schema dumps and multipass-sized row fetches (never an unbounded dump). GUIDE_deploy_from_context_packs.md documents the general operating loop (attach pack → gather live context → verify the decisive fact → work → deploy → verify with positive evidence) and a deploy-mechanisms taxonomy used to scope any task before touching it: (A) chassis platform image — rebuild/push/retag + k8s rollout; (B) database/migrations — psql, snapshot-first, re-query to verify; (C) work-items — insert a site_work_items row for the dispatch loop; (D) orchestration trigger — a kcat `orchestrate` message; (E) generated static sites — downstream via git → GitHub Actions → Backblaze once build_status='deployed'; (F) the idea.uk binary — a separate non-k8s, file-based Go binary with its own build/scp/restart cycle. Cross-cutting cautions baked into the guide: bump image tags or a rollout won't pull the change; "complete" is not "succeeded" — verify positive evidence, not just terminal status. Known operational failure modes recorded across instances: unquoted parentheses in doc paths break bash; an empty `/tmp/analysis_repo.json` breaks analysis load; a bundle can't reach session docs that live outside the repo.
