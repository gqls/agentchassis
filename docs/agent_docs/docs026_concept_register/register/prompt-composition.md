### PRC-001 — Mega-prompt fragility and candidate replacement patterns
- **status:** aspirational
- **status-evidence:** "Treat the existing 6KB text prompt as technical debt, not a model … Not blocking imagery or anything else; just don't propagate the pattern" (undated FOCUS doc, ~2026-05).
- **what:** page-content-writer's single ~6KB prompt blends 11+ inputs, 16 growing STRICT RULES, and six worked output schemas. Six fragility concerns were identified: untraceable failures, monotonic rule growth, coupled component vocabulary, a single blend ratio, model coupling, and token waste at scale (roughly 160MB/build-cycle). Five candidate replacement patterns were proposed: per-component templates; a structured intermediate envelope (a cheap-model stage 1 producing a cacheable/lockable structure consumed by a focused stage 2); tool-calling to enforce schema; validation-instead-of-prompt-rules; and a hybrid baseline+overrides approach. The structured-envelope pattern is flagged as strongest for both text and image generation, but none of the five had been implemented at time of writing — this is a design proposal, not a shipped change.
- **sources:** FOCUS_prompt_composition_pattern.md (whole)
- **relations:** image parameter shaping; validate_page_content (a partial existing instance of the validation-instead-of-rules pattern); array-item field contract for the page-content-writer (development-guide DEV-021, a concrete symptom of this same mega-prompt fragility); LLM reliability strategy

### PRC-002 — Logo text policy enforced at the generation choke point (not at the prompt's source)
- **status:** built 2026-08-31, **INERT until the next chassis roll** (Go); the accompanying data wash (migration 680) IS applied and live.
- **status-evidence:** committed `8bcd4ccae`; council `Council-Submitted: bb099a3d-0555-4fcf-b12a-31652b59f8b9` (verdict pending at time of writing — do NOT read this entry as an approved verdict). Migration 680 applied 2026-08-31, verified at the row: 0 wordmark-mentioning current logo prompts lack a governing clause.
- **what:** A per-kind text policy applied inside `GenerateImageAction` (`generate_image_actions.go`, `applyLogoTextPolicy`), immediately after the kind-gated imagery-direction block and before the prompt goes to the adapter. Every `kind=logo` prompt gets `checks.LogoTextFreeClause` appended — a POSITIVE-framed instruction that explicitly voids any earlier wording permitting a wordmark — plus lettering terms folded into `negative_prompt` as belt. An opt-in escape hatch, `input_data.spec.constraints.wordmark_text`, permits a deliberately lettered mark **only when its value is the exact string**, validated against the site's own `company_name` / `logo_text` / domain stem; a mismatch DEGRADES to text-free with a Warn rather than refusing (bugs_open/210's unhandleable-item lesson). Idempotent on `checks.LogoTextFreeSentinel`; tags `prompt_source` with `+logo_text_policy` so a census can tell the guard fired, and because `assets.origin_prompt` records the composed prompt the clause is **visible in the artefact**. The clause constants live in `discovery_checks/default_brand_prompt.go` and are shared with the fallback builder, pinned by a parity test.
  **WHY THE PLACEMENT IS THE POINT (bugs_open/417).** The estate had this rule since 2026-08-09 — but coupled to the prompt's SOURCE, inside the FALLBACK builder that runs only when a plan carries no logo prompt. Every planner-built site carries one, so the rule governed exactly the population that never needed it. Moving it to the choke point couples it to the asset's PURPOSE instead: it now governs every tier `getImagePromptWithPriority` collapses, every producer present and future, and **work items already queued** with an unwashed prompt — which a config migration structurally cannot reach.
  **Two measured facts a caller should not re-derive.** (1) A folded NEGATIVE prompt LOSES to a positive licence in the same prompt: the failing boxingonline generation received "text" in its negative list (banana adapter fold log, 2026-08-31 12:55:50Z, len 232→407) and lettered "BOXING NEWS" anyway. Negative-only text control does not work; that is why the clause is positive and says it overrides. (2) The model REWORDS a licence it was given ("no text **other than** the wordmark" from an exemplar saying "**outside**"), so **no literal match bounds this class** — a census keyed on a literal measures its own literal. Count the licence CONCEPT (a wordmark permitted without the brand string named), or count this policy's own tag.
- **sources:** `platform/orchestration/actions/generate_image_actions.go` (`applyLogoTextPolicy`, `logoIdentity`, `wordmarkGroundsInIdentity`, `stripLogoTextNegatives`); `platform/orchestration/actions/discovery_checks/default_brand_prompt.go` (`LogoTextFreeClause`, `LogoTextFreeSentinel`, `LogoWordmarkClause`); tests `generate_image_logo_policy_test.go`, `discovery_checks/logo_clause_parity_test.go`; `bugs_open/417`; migrations 669/670 (loanzy lane) and 680 (this lane).
