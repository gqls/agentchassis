### PRC-001 — Mega-prompt fragility and candidate replacement patterns
- **status:** aspirational
- **status-evidence:** "Treat the existing 6KB text prompt as technical debt, not a model … Not blocking imagery or anything else; just don't propagate the pattern" (undated FOCUS doc, ~2026-05).
- **what:** page-content-writer's single ~6KB prompt blends 11+ inputs, 16 growing STRICT RULES, and six worked output schemas. Six fragility concerns were identified: untraceable failures, monotonic rule growth, coupled component vocabulary, a single blend ratio, model coupling, and token waste at scale (roughly 160MB/build-cycle). Five candidate replacement patterns were proposed: per-component templates; a structured intermediate envelope (a cheap-model stage 1 producing a cacheable/lockable structure consumed by a focused stage 2); tool-calling to enforce schema; validation-instead-of-prompt-rules; and a hybrid baseline+overrides approach. The structured-envelope pattern is flagged as strongest for both text and image generation, but none of the five had been implemented at time of writing — this is a design proposal, not a shipped change.
- **sources:** FOCUS_prompt_composition_pattern.md (whole)
- **relations:** image parameter shaping; validate_page_content (a partial existing instance of the validation-instead-of-rules pattern); array-item field contract for the page-content-writer (development-guide DEV-021, a concrete symptom of this same mega-prompt fragility); LLM reliability strategy
- **verify-later:** page-content-writer default_config prompt size/shape today — has any of the five candidate patterns since been adopted?

### PRC-002 — Logo text policy enforced at the generation choke point (not at the prompt's source)
- **status:** built 2026-08-31, **INERT until the next chassis roll** (Go); the accompanying data wash (migration 680) IS applied and live.
- **status-evidence:** committed `8bcd4ccae`; council `Council-Submitted: bb099a3d-0555-4fcf-b12a-31652b59f8b9` (verdict pending at time of writing — do NOT read this entry as an approved verdict). Migration 680 applied 2026-08-31, verified at the row: 0 wordmark-mentioning current logo prompts lack a governing clause.
- **what:** A per-kind text policy applied inside `GenerateImageAction` (`generate_image_actions.go`, `applyLogoTextPolicy`), immediately after the kind-gated imagery-direction block and before the prompt goes to the adapter. Every `kind=logo` prompt gets `checks.LogoTextFreeClause` appended — a POSITIVE-framed instruction that explicitly voids any earlier wording permitting a wordmark — plus lettering terms folded into `negative_prompt` as belt. An opt-in escape hatch, `input_data.spec.constraints.wordmark_text`, permits a deliberately lettered mark **only when its value is the exact string**, validated against the site's own `company_name` / `logo_text` / domain stem; a mismatch DEGRADES to text-free with a Warn rather than refusing (bugs_open/210's unhandleable-item lesson). Idempotent on `checks.LogoTextFreeSentinel`; tags `prompt_source` with `+logo_text_policy` so a census can tell the guard fired, and because `assets.origin_prompt` records the composed prompt the clause is **visible in the artefact**. The clause constants live in `discovery_checks/default_brand_prompt.go` and are shared with the fallback builder, pinned by a parity test.
  **WHY THE PLACEMENT IS THE POINT (bugs_open/417).** The estate had this rule since 2026-08-09 — but coupled to the prompt's SOURCE, inside the FALLBACK builder that runs only when a plan carries no logo prompt. Every planner-built site carries one, so the rule governed exactly the population that never needed it. Moving it to the choke point couples it to the asset's PURPOSE instead: it now governs every tier `getImagePromptWithPriority` collapses, every producer present and future, and **work items already queued** with an unwashed prompt — which a config migration structurally cannot reach.
  **Two measured facts a caller should not re-derive.** (1) A folded NEGATIVE prompt LOSES to a positive licence in the same prompt: the failing boxingonline generation received "text" in its negative list (banana adapter fold log, 2026-08-31 12:55:50Z, len 232→407) and lettered "BOXING NEWS" anyway. Negative-only text control does not work; that is why the clause is positive and says it overrides. (2) The model REWORDS a licence it was given ("no text **other than** the wordmark" from an exemplar saying "**outside**"), so **no literal match bounds this class** — a census keyed on a literal measures its own literal. Count the licence CONCEPT (a wordmark permitted without the brand string named), or count this policy's own tag.
- **sources:** `platform/orchestration/actions/generate_image_actions.go` (`applyLogoTextPolicy`, `logoIdentity`, `wordmarkGroundsInIdentity`, `stripLogoTextNegatives`); `platform/orchestration/actions/discovery_checks/default_brand_prompt.go` (`LogoTextFreeClause`, `LogoTextFreeSentinel`, `LogoWordmarkClause`); tests `generate_image_logo_policy_test.go`, `discovery_checks/logo_clause_parity_test.go`; `bugs_open/417`; migrations 669/670 (loanzy lane) and 680 (this lane).

### PRC-003 — a prompt's unresolvable reference is NAMED, STRIPPED and escalated inside a do-not-invent block, instead of being counted and sent
- **status:** **BUILT + TESTED 2026-09-03, NOT LIVE** (Go — rides the next chassis roll). Carried by **`681b0ee65`**, so "did it ship?" is a query rather than an inference: `git merge-base --is-ancestor 681b0ee65 <the service's build-provenance stamp>`. `bugs_open/453` shape 3, raised as a correction to 453 by the `bugs_open/437` lane. Diagnosis `92309b45` filed BEFORE the root cause was asserted (090); council submission alongside.
- **what:** `text/template` renders a reference it cannot resolve as the literal `<no value>`, and `RenderPromptTemplate` used to **send that string to the model** — so a prompt could read `Location: <no value>` inside a block headed *"Official Contact Information (USE ONLY THESE - DO NOT INVENT)"*. `[MEASURED 2026-09-03, 437 lane]` roughly **65%** of `page-content-writer` prompts carried at least one. The only signal was a `Warn` that counted occurrences and named no field.
  Now: **named** (`unresolved_paths`, dotted — `reviewed_brief.headquarters`, not `reviewed_brief`), **stripped** before send, and **Error instead of Warn** when an occurrence sat inside an anti-invention block. Report-only; it never refuses (owner ruling 2026-08-02 §2 — refusing is new authority over prompts that render fleet-wide today; what this closes is the SILENCE).
- **why stripping is right HERE and wrong on a page:** the sibling seam's LANDMINE warns that a stripped blank is *worse* than a visible break, because a human cannot see what is absent. In a prompt the reader is a MODEL, and the two are not symmetric: `Location: ` says there is no location, which is true; `Location: <no value>` asserts the location IS that string, and the surrounding instruction vouches for it. Structurally `bugs_open/387`'s shape (a stand-in inside instructed copy, measured there at 14 of 137 calls) with **no human author** — the renderer manufactures it.
- **the escalation rule is MEASURED, and that is the load-bearing part.** Across the **139** live prompt templates (2026-09-03): `exact` **161** occurrences, `verified` **73**, and **87 of 139** templates carry one or the other — so a marker set including them, or a document-level rather than block-level test, escalates nearly every render, and a severity that fires on two thirds of the fleet is not a severity. The set is anti-INVENTION directives only (`do not invent` 27, `never invent` 22, `use only` 12, `only these` 3 = **64**), and the test is **block-scoped** — bounded by the nearest blank line, because a paragraph is the unit the instruction governs.
- **exact vs best-effort, kept separate on purpose:** `Occurrences` and `Authoritative` are counted in the RENDERED OUTPUT and cannot be wrong about whether it happened. `Fields` is attributed from template + data and is **short by design** — inside `{{range}}`/`{{with}}` the dot is a loop item the scan cannot see. An empty field list therefore LOGS THAT IT IS EMPTY BECAUSE THE SCAN COULD NOT SEE, never a bare `[]` that reads as "no fields affected".
- **⚠ it does NOT call `ExtractNestedField`,** and that is deliberate: that helper is a RESOLVER with fallbacks (retries under `input_data`, unwraps `response` envelopes, indexes arrays), so it answers *"can this be found?"* while the template asked *"is this here?"*. Using it would report a path as resolvable that the template had already rendered as a hole — the one wrong answer this must never give. `pathResolves` mirrors `text/template`'s own map indexing, and **present-but-nil does NOT resolve**, because that is what emits the token.
- **blast radius:** `RenderPromptTemplate` has **4** call sites as of 2026-09-03 — `ExecuteLLMPromptAction`, `ExecuteVisionPromptAction`, and the tier-1 parent-prompt interpolation in `ai_actions.go` and `generate_image_actions.go`. The last two interpolate against raw `CollectedData` rather than the extracted template data, so they see a different map; the strip and the report are correct for both shapes.
- **five mutation proofs, each RED:** strip removed · block scope widened to the document · marker set widened to `verified|exact` · present-but-nil counted as resolved · range bodies attributed.
- **sources:** `bugs_open/453` (§3 shape 3 + the 437 lane's contribution), `platform/orchestration/datahelpers/template_missing_values.go`, `RenderPromptTemplate` in `data_helpers.go`.
- **relations:** the CONFIG-side sibling is **WFA-024**, which closes shape 2 and structurally cannot reach shape 3 (the config is correct; the outcome depends on a row). The PAGE-side sibling is `missingBareFields` + the report around it in `component_library.go`, whose answer this mirrors — and which deliberately **excludes** nested access (`{{.Foo.Bar}}`), which is exactly the failing case here. `bugs_open/387` (stand-in tokens in instructed copy), `bugs_open/018` (the count-only Warn that let 30 dead controls ship).
- **verify-later:** after the roll, `kubectl logs -l app=agent-chassis | grep 'PROMPT RENDERED'` should show Warn traffic immediately (the 65% population) and Error only where a hole lands in an anti-invention block. **A total silence is the suspect result**, not the good one — it would mean the seam is not being reached.
