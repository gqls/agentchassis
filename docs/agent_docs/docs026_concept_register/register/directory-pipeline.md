### DIR-001 — Global verified-claim provider/entity directory (one kind = one fleet-wide list)
- **status:** deployed (kinds model/company/protocol); built-awaiting-roll (kinds mortgage-lender/savings-provider/health-insurer, Phase B 2026-08-13)
- **status-evidence:** directory_entities live distribution 2026-08-10 (FINDING doc): company 32, model 27, protocol 4, all with current found claims; `SEED_directory_publish_trigger.sql` + Phase E council approval (`c67ecb24-eb0e-4...`, cited in `directory_registration_test.go`); Phase B Go profiles committed 2026-08-13, inert until image roll + seeds.
- **what:** A GLOBAL, cross-site registry (`directory_entities` UNIQUE(kind, slug) + `directory_claims`, migration 192) of entities whose every fact carries a verbatim-quote citation, re-verified live: the researcher chain (web_search → prepare_urls → batch_webscrape → LLM extract_claims → `verify_and_register_directory_claims`) registers a claim ONLY if its quote is present in the re-fetched source ("the model proposes; the string comparison disposes", `directory_claims.go`). Per-kind rendering is a closed profile set: `directoryCheckProfiles` (discovery checks per kind: `missing_<x>_section`/`_page`) + `directoryPublishProfiles` (render_directory → JSON files + components) + queryresolve case arms (`<spec_key>`/`<spec_key>_full`) + content_components rows. **The load-bearing guarantee: one kind = one identical list on every opted-in site** — `QueryDirectoryEntries` filters only `kind`+`status`, never site. Per-site filtering would change that guarantee and is architecture-review scope (deliberately avoided by one-kind-per-provider-class). Adding a kind is data-only across six places (profiles ×3, components, checks-array enablement, planner prompt) — NO schema migration (`kind` is unconstrained text).
- **producer set (RFC_010 condition):** `directory-researcher` (kind model), `adoption-researcher` (kinds company+protocol from one prompt), `finance-directory-researcher` (Phase B: kinds mortgage-lender, savings-provider, health-insurer from one prompt; seeds in `docs024_key_docs_latest/finance_directory_pipeline/`). All converge on `verify_and_register_directory_claims`; entity dedupe key is UNIQUE(kind, slug), upsert-by-slug.
- **item_key shapes:** review items are HITL-terminal at the system pseudo-site (`directorySystemSiteID`), keyed PER KIND since Phase B: `directory_citation_unverified:<kind>` and `stale_directory_claim:<kind>` (a batch whose candidate carried no entity_kind groups under the bare legacy key rather than being dropped). Before Phase B both keys were CONSTANTS — one row for the whole registry, the coarsest bugs_closed/091-class instance in the tree (see batch-processing.md's note); kind-scoping changed key GRANULARITY only, refreshOnConflict policy unchanged.
- **finance-kinds fact policy (owner ruling 2026-08-12/13, compliance):** NON-PRICE facts only — FCA firm reference, regulator status, product types, underwriter, established year. Never APR/rates/premiums (a stale price under a named regulated firm is a financial-promotion exposure). Enforced in the researcher prompt; stated here so a future kind-adder inherits the rule.
