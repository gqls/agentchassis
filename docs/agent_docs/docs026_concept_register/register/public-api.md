### PUB-002 — `platform/httpguard`: inbound-abuse primitives for public HTTP endpoints, with the trusted proxy stated per deployment
- **status:** built, unit-tested, council-approved (`6db59c8b`) — ~~**and called by NOTHING.** Zero importers, re-measured 2026-07-29.~~ **ADOPTED 2026-07-31: it has its first real consumer, and the adoption is LIVE and PROVEN in production.** Owner-ruled remit ("get it adopted", 07-29) is discharged for one of the two named call sites' services.
- **status-evidence:** ~~returns only the package itself~~ **re-measured 2026-07-31, as this entry's own instruction requires: `grep -rn 'agentchassis/platform/httpguard' --include=*.go . | grep -v '^./platform/httpguard/'` returns `internal/tools-api/clientip/clientip.go:59`.** Live proof, island `aqls/tools-api:v1.0.1207` swapped 2026-07-31 08:37Z: a real `/round` through Cloudflare stored `client_ip_hash = 9e464fe9fca925b099a25141f40afad5`, which is `sha256(<the caller's own egress address, as CF reported it>)[:16]` **computed independently before the request was sent** — so the value did not merely change, it changed to the one predicted. `count(DISTINCT client_ip_hash)` on `gauntlet_rounds` went **1 → 2** (95 prior rows all being the docker-gateway constant `245c0ffc…`). Pre/post on the RUNNING container with controls in both directions: `CF-Connecting-IP` and `cloudflare-tunnel` were **0/0 before** and **1/1 after**, `gin-gonic` 1186 before (so the zeros were real absences, not a broken `strings`), nonsense token 0 after. `go test ./platform/httpguard/` still passes.
- **what this settles that unit tests could not:** the `open review question` below asks whether `CF-Connecting-IP` genuinely reaches an adopting app process. **It does** — that was `[INFERRED]` in `bugs_open/139` because nobody would add a header-echo endpoint to another team's service, and it is now measured at the artefact instead. Note what is still NOT closed: the peer-gate reversion on a real *public* peer remains structurally unclosable locally, exactly as recorded below.
- **what:** One shared implementation of three things that had diverged across the estate: `ClientIP` (a per-client key the client cannot choose), `Limiter` (in-memory sliding-window, multi-band, returns retry-after — replaces a single token bucket that could express only one ceiling and no retry-after), and `CheckIntake` (honeypot + client-side timing gate, fail-open on missing JS). net/http only, no gin, so a gin service writes a three-line adapter. Written because three per-IP limiters existed and **the weakest guarded the only public endpoint**, and four different CORS postures existed.
- **the seam, and the landmine it exists to close (2026-07-29):** `ClientIP` takes a **required `FrontEnd` argument** naming which headers *this deployment's* proxy is known to **write** (as opposed to merely forward). Pre-declared: `Nginx()`, `CloudflareTunnel()`, `Direct()`. It previously hard-coded nginx's rules — prefer `X-Real-IP`, else the rightmost `X-Forwarded-For` — justified in its own docstring by nginx's `proxy_set_header` behaviour. **That justification is false on the estate's other front-end.** Measured 07-29: Caddy does not set `X-Real-IP` and forwards a client-supplied one verbatim, and it *overwrites* `X-Forwarded-For` with its own peer instead of appending. So on the island both old rules resolve to either user input or a constant, and adopting the old default into `tools-api` would have keyed every visitor on the docker bridge gateway — **83 of 83 rows, one distinct value** — while reading like a fix. The argument is required precisely so that a caller cannot inherit an assumption it never stated.
- **open review question:** the peer gate (`loopback || RFC1918`) is what keeps `CloudflareTunnel()` honest — trusting `CF-Connecting-IP` is trusting Cloudflare to be in front, and the gate is what makes the header revert to being ignored if the origin is ever reachable without the tunnel. Nobody has tested that reversion against a real direct-exposure path, only in unit tests. **The `architecture` seat ruled on this at review (2026-07-29, corr `49392838`, severity low): *"Fine to ship, but the open question should not go stale - the next thing to land against this package should close it, not add a fourth FrontEnd."* Treat that as the package's next obligation, ahead of any new front-end.**
  - **DISCHARGED as far as it can be, same day, and the residue is stated rather than left implied.** `TestPeerGateBoundaryIsStatedNotAssumed` now pins where the gate actually falls across ten realistic address forms, and `TestClientIPParsesTheRemoteAddrARealSocketProduces` drives a real `httptest` socket so the peer is parsed from what the *runtime* puts in `RemoteAddr`, not from a hand-typed string — the case where a bug would really hide, since a leaked port or bracket would fragment every limiter bucket per-connection. Both were verified to FAIL under targeted mutation (removing `IsPrivate` from the gate; returning `RemoteAddr` verbatim), so neither is a check that cannot fail.
  - **What remains structurally unclosable locally:** a genuine connection from a real *public* peer. Every address a dev machine can bind is loopback or RFC1918 and so lands on the trusted side of the gate by construction. It can only be closed by a real direct-exposure deployment, and that is a deployment question, not a test one.
  - **Boundary fact worth knowing before adopting:** Go's `net.IP.IsPrivate` covers RFC1918 and RFC4193 **only**, so a proxy behind **CGNAT (`100.64.0.0/10`)** or on a link-local address is **NOT** trusted and its headers are ignored. That fails in the safe direction — a coarse key rather than a spoofable one — but it is a real constraint on where this package can be deployed, now pinned by test rather than discovered in production.
- **council (round 1, 2026-07-29, corr `49392838-5ada-4c8e-baeb-94b01e5855b4`):** **APPROVED** — *"approved with 1 advisory objection(s) — none high-severity"*. 9 seats fired, 8 abstained on relevance, none unreadable. (b) *Decommissioning* has **not**, and the adoption did not attempt it — what changed is the **key** the existing token bucket is keyed on (`middleware/ratelimit.go:30`, `handlers/round.go:109`), not the limiter implementation. `httpguard.Limiter` still has **zero** consumers, and all three divergent limiters still exist. Measured 2026-07-31: `grep -rn 'httpguard\.\(Limiter\|NewLimiter\|CheckIntake\)' --include=*.go . | grep -v '^./platform/httpguard/'` → **nothing**, and `middleware/ratelimit.go:9` still imports `golang.org/x/time/rate` with its own `map[string]*rate.Limiter` — the diff swapped `c.ClientIP()` for `clientip.From(c)` at `:33` and nothing else.
