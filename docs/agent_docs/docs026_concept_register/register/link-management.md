Masking the spans to a same-length filler BEFORE matching removes the decoy and leaves the real anchor to be matched alone, with offsets that still index the original bytes.
- **⚠ LANDMINE — the FILLER is load-bearing and a space is the wrong byte.** A whitespace filler can MANUFACTURE a match the document never contained: `\ssrc\s*=\s*""` cannot cross `<style>…</style>`, but it crosses the spaces that replaced it, and that match begins OUTSIDE the span where the offset filter has no view — deleting the style element and the attribute together. The discriminating input must begin outside the span; the test now asserts its own premise (`NonMarkupSpans` found the element) so it cannot quietly stop discriminating.
- **the two span sets degrade in OPPOSITE directions, from one walk:** `RuntimeFillSpans` is an EXEMPTION for judges, so unparseable markup widens it to the historical whole-input skip (LNK-025). `NonMarkupSpans` is a KEEP-OFF for writers, so an unclosed raw-text element, an unterminated comment or an unterminated quote in a start tag makes the REMAINDER non-markup — a writer that cannot locate the rest of the document declines to rewrite it, which is `link_repair.go`'s stated fail-safe direction. Both widen under uncertainty; they differ in what widening protects.
