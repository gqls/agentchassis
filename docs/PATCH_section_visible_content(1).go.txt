// PATCH — platform/orchestration/actions/rerender_single_page_action.go
// Function: sectionHasVisibleContent  (+ one package-level regexp)
//
// WHY
// ---
// getPageSections drops any section whose rendered_html has <=10 chars of visible text
// after stripping <style>/<script>/tags/entities/whitespace (sectionHasVisibleContent).
// That correctly filters genuine empty shells / generation failures. But it also drops
// sections that are INTENTIONALLY empty at build time and populated client-side by a
// loader — e.g. the daily provocation-card, whose Path-2 loader fills it in the browser.
// Those sections have essentially no build-time text and were being filtered out, so
// provocation-card never reached the deployed page.
//
// NOTE: the inline <script> is stripped before measuring, so it never contributed to the
// decision — this is a visible-text filter, not a script filter. The extraction bug
// (js_content empty) is unrelated to this drop.
//
// FIX
// ---
// A section may declare `data-runtime-fill` (any attribute value) to signal it is filled
// at runtime. sectionHasVisibleContent returns true (keep) for such a section regardless
// of build-time visible text. Sections WITHOUT the marker are still filtered exactly as
// before, so genuine empty shells (and not-yet-built shells like lobby-grid) are still
// dropped.
//
// SCOPE / SAFETY
// --------------
// - Signature unchanged. Adds one package-level regexp (reRuntimeFill) alongside the
//   existing precompiled regexps, and one early return in sectionHasVisibleContent.
// - No variable renames.
// - Only sections that explicitly carry data-runtime-fill are exempted; everything else
//   behaves identically. This is strictly additive.
// - The marker must be added to the runtime-filled component's template (and its current
//   page_components.rendered_html) — see the accompanying SQL. Do NOT mark lobby-grid: it
//   has no loader/content yet and should stay filtered until built.

// --- add to the existing package-level var ( ... ) block ---
var reRuntimeFill = regexp.MustCompile(`(?i)data-runtime-fill`)

// --- replace sectionHasVisibleContent with: ---

// sectionHasVisibleContent reports whether the given rendered HTML should be kept in the
// assembled page. Sections explicitly marked data-runtime-fill are intentionally empty at
// build time (a client-side loader populates them) and are always kept. Otherwise the
// section is kept only if it contains more than 10 characters of visible text after
// stripping <style>/<script> blocks, HTML tags, HTML entities, and whitespace — sections
// with less than that aren't meaningful build-time content and represent a generation
// failure or a stale/not-yet-built empty shell, which shouldn't reach the deployed page.
func sectionHasVisibleContent(html string) bool {
	if html == "" {
		return false
	}
	// Runtime-filled sections (e.g. the daily provocation card) are intentionally empty
	// at build time; a browser-side loader fills them. Keep them regardless of build-time
	// text. Genuine empty shells do not carry this marker and are filtered below.
	if reRuntimeFill.MatchString(html) {
		return true
	}
	s := reStyleBlocks.ReplaceAllString(html, "")
	s = reScriptBlocks.ReplaceAllString(s, "")
	s = reHTMLTags.ReplaceAllString(s, "")
	s = reHTMLEntities.ReplaceAllString(s, "")
	s = reWhitespace.ReplaceAllString(s, "")
	return len(s) > 10
}
