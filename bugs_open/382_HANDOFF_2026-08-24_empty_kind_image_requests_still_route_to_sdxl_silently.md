# 382 — image requests with an EMPTY `kind` still route to SDXL, silently — 15 heroes on 5 sites since the routing fix, none of them chosen

**Filed:** 2026-08-24, vetcomparison lane. **Status:** OPEN — evidenced symptom + measured blast
radius + a named candidate mechanism; the caller-side half is DELIBERATELY not diagnosed to a
root cause here (see §5 — it needs one read the filing lane did not do, per the diagnosis-before-
debugging rule this file is complying with).
**Parent:** `bugs_open/011` (hero routing — fixed 2026-07-18 by the routing table). This is the
door 011's fix left open, by documented design, that production traffic is still walking through.

## 1. Symptom, as the owner met it

The owner reported "the image of a nurse … has weird eyes reminiscent of the early image
creators" on vetcomparison.uk and asked whether it is a model choice or a prompt choice. It is a
**model** choice: the image is SDXL output (`origin_model='stability/stable-diffusion-xl-1024-v1-0'`,
asset `8d5e6495`, generated **2026-07-17 — one day before** `hero` was routed to banana/Gemini by
011's fix). That site's relics are being regenerated by its own lane. **This file is about what
the census found on the way: SDXL is still producing NEW heroes, after the fix, fleet-wide.**

## 2. The measured facts (all 2026-08-24)

- **15 hero assets on 5 sites generated by SDXL AFTER the 07-18 routing fix**, latest 2026-08-11:
  ai-agent-orchestration.com (5, last 08-11), mortgagecalculator.co.uk (1, 08-11),
  leopardessconsulting.co.uk (1, 08-08), gaswholesalers.com (3, 08-03), finetuning.uk (5, 08-03).
  Query: `SELECT s.domain, a.purpose, count(*), max(a.created_at) FROM assets a JOIN sites s ON
  s.id=a.site_id WHERE a.origin_model='stability/stable-diffusion-xl-1024-v1-0' AND
  a.created_at > '2026-07-18' GROUP BY 1,2;`
- **The documented escape hatch does not explain them.** The only sanctioned route to SDXL for a
  routed kind is `provider:"stability"` in the site's `imagery_style_guide`
  (`site_specs.aspect='imagery_style_guide'`, read by `getImageryStyleGuideForSite`,
  `platform/orchestration/actions/imagery_style_guide.go:86-97`). Of the 5 sites, only
  leopardessconsulting.co.uk and finetuning.uk HAVE a current guide row, and **neither carries a
  `provider` key**; the other 3 have no current guide at all.
- **No live agent definition pins a stability model** — `jsonb_path_query(default_config,
  '$.**.model')` ILIKE '%stability%' over active, non-snapshot rows: **0**.
- The healthy path works: every hero generated 2026-08-15→24 (8 of 8, agritec.uk today) is
  `banana/gemini-3-pro-image-preview`, via `needs_hero_image → image-build-handler`.

## 3. The named candidate mechanism (in the router's own words)

`internal/adapters/imagegenerator/routing.go` (read 2026-08-24): `routeProvider` falls through to
**Stability** when `kind` is empty, and the `UnmigratedKind` warning is deliberately NOT set for
that case — the comment says *"An EMPTY kind does not set this: legacy callers that predate the
field are a documented, deliberate Stability path, not an oversight."* So an empty-kind request
gets the weak model **with no warning anywhere** — the exact silence 011's table was built to end
for the named-kind case. The `reported_conditions` channel (persisted to `agent_error_log`) has
nothing to persist for it.

## 4. Why this is a defect and not a documented behaviour

The design assumption was that empty-kind callers are *legacy* and *deliberate*. The measurement
says the traffic is neither: 15 **hero** generations (a kind the table routes!) landed on SDXL
without any site or agent choosing it. Whatever built those requests dropped/never set `kind`, so
the routing fix is bypassed for real hero traffic, and the failure is invisible — generation
reports success, the site gets 2023-era face artefacts, and a human notices months later. That is
the identical failure shape 011 documented, one field to the left.

## 5. What the fixing lane should do (candidates, ordered by door-closing)

1. **Find the empty-kind caller(s).** One read the filing lane deliberately did not do: which
   producer built those 5 sites' generation requests 08-03→08-11 (candidates: rerender-side
   regeneration, brand-head asset path, an older `generate_image` step config missing a `kind`
   input). `agent_error_log` cannot answer it (that is the defect); the orchestration rows for
   those generations can.
2. **Close the default**: empty kind → banana (the strong provider), not stability — or refuse.
   The "legacy deliberate" premise is refuted by §2; if a genuine legacy caller exists it can say
   `provider:"stability"` like everyone else. One-line change in `routeProvider` + tests; council
   (platform scope).
3. **At minimum, make the silence loud**: set a reported condition for empty-kind fallbacks so
   `agent_error_log` shows them — that converts the next occurrence from an owner complaint into
   a queryable row.

## 6. How to verify a fix

Re-run the §2 census with the fix's deploy date substituted for '2026-07-18' after a couple of
weeks of builds: the SDXL row set must be empty (or every row must trace to an explicit
`provider:"stability"` hint). Negative control: banana heroes keep appearing.
