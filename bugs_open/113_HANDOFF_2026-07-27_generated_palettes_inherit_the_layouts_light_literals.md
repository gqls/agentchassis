# 113 — a generated palette defines 8 slots, the layout declares 17, and the other 9 ship as light literals on dark sites

**Filed:** 2026-07-27 by the brochure_component_library workstream, after the owner
reported that fundamentallyai.com was "nothing like the brief" on mobile, with grey
text unreadable on white and no visible chart. Found by **rendering the served pages
and measuring them**, not by reading code — every input involved is individually valid.
**Severity:** High. It is not a cosmetic defect: on the worst-hit pages the card titles,
the chart labels and the chart values are all invisible, so the page reads as empty
rather than as badly coloured.
**Class:** structural, composition-level. Nothing is wrong with any single input; the
defect exists only in the merge.
**Status:** OPEN. Fixed in code (`3096a55a6`) and **inert until the next chassis roll**.
The affected site was repaired at the data level in the same session, which does not
close it: 11 other palettes still carry the trap and reproduce it on their next
stylesheet render.

**Sibling of `bugs_closed/022`**, which is the same merge, the same function, and the
opposite half of the same contract. 022 was "the spec's core slots win and nothing
checks the *result*". This is "**the slots the spec never supplies fall through to the
layout's literals and nothing checks those either**". 022 was closed by a guard on one
value; the class it belongs to was not.

---

## Symptom, measured

`scripts/render_audit.py` renders each page in headless Chromium, walks every visible
text node, composites the effective background through transparent ancestors, and
computes the WCAG ratio of the pair that is actually on screen.

```
$ scripts/render_audit.py --sitemap https://fundamentallyai.com/index.html
   index.html                     contrast=47
   capabilities.html              contrast=18
   multi-agent-review-council.html contrast=23
   about.html                     contrast=8
   contact.html                   contrast=5
   → 101 WCAG-AA failures across 5 pages
```

Three examples, each a different mechanism:

| ratio | pair | where |
|---|---|---|
| 1.21:1 | `rgb(228,234,242)` on `rgb(255,255,255)` | `.info-card-grid__card-title` — "Every decision leaves a record", the owner's own example |
| 1.21:1 | same pair | `.evidence-chart__label` / `__value` — the chart the owner could not see |
| 1.11:1 | `rgb(14,27,46)` on `rgb(8,14,28)` | every `__eyebrow`, every carousel link, six differentiator card titles |
| 1.03:1 | `rgb(14,27,46)` on `rgb(17,30,51)` | H3 card titles on the surface sections |

## Cause

### (a) the fall-through

`layouts.css_template` for `brochure-formal` declares seventeen palette slots, each
with a hard-coded fallback:

```
  --color-card-bg:        {{palette "card_bg"        "#ffffff"}};
  --color-header-bg:      {{palette "header_bg"      "#ffffff"}};
  --color-cta-bg:         {{palette "cta_bg"         "#1a365d"}};
```

That is the Template Helper Fallback contract working as designed. But
`corePaletteKeys` (`render_css_composition_helpers.go:41`) is exactly eight names,
and a per-site palette generated by the design pipeline contains **only those eight**.
So nine slots take the layout's literals on every render, and those literals were
written for a light-scheme layout.

`palettes` row `c7c5435f` (palette-fundamentallyai-com), verbatim:

```json
{"text":"#E8EDF3","accent":"#C8902A","border":"#1E3050","primary":"#0E1B2E",
 "surface":"#132239","secondary":"#1A2E48","background":"#090F1A","text_muted":"#8A9BB0"}
```

A `#ffffff` card, and `--color-text: #E8EDF3` landing on it.

**The failure is silent in the strongest sense: a derived value and a curated one are
indistinguishable in the output CSS.** Reading the served stylesheet, `--color-card-bg:
#ffffff` looks like somebody's decision.

### (b) one token, two roles

`--color-primary` is used by the component library as a **foreground** far more often
than as a fill — 53 `color:` uses against 26 `background:` uses across this site's
pages. A palette whose primary sits in the same family as its background therefore
renders every eyebrow, link and card title invisible **while every fill still looks
correct**. That asymmetry is why the page reads as missing text.

### (c) the section-defaults picker preferred the muted colour

Independent of (a) and (b), and in the same render path. `paletteTextPreference`
(`color_util.go`) listed `text_muted` ahead of `text`, so `buildSectionDefaults`
emitted, on every dark site:

```css
body { --section-text: #7E91A8; --section-heading: #7E91A8; }
```

— the palette's *dimmest* reading colour, for body copy **and** headings, while
`#E4EAF2` sat unused in the same palette. Its thresholds were 3.0 for body and 2.0 for
headings, both below any published readability floor, justified in-comment as
preserving palette character. And the palette slot `heading`, defined by 15 of 31
palettes, was read by nothing.

## Blast radius, measured fleet-wide

Over all 31 rows of `palettes`:

- **16 define no `card_bg`**, so the `#ffffff` literal is what renders.
- **12 of those 16 have a dark background AND a light `text`** — a guaranteed
  white-card-with-invisible-text. Contrast of `text` against the literal:
  vonc.com 1.14, dartsonline.com 1.12, fundamentallyai.com 1.18, oufe.com 1.29,
  gamedesign.uk 1.32 (eight palette versions).
- **4 have a `primary` below 3:1 on their own background**: dartsonline.com 1.11,
  fundamentallyai.com 1.11, robot-hands.com 1.14, oufe.com 1.21.

The four light palettes with no `card_bg` (idea.uk, relojistas.com, vetcomparison.uk,
webdesign.co.uk) are **fine** — the literals suit them, which is why the fix is scoped
to dark backgrounds.

### Confirmed on three other live sites by rendering them, not by arithmetic

The counts above are computed from palette values. This is the same question asked of
the served pages, and it agrees — **60 further failures on three homepages alone**:

```
$ scripts/render_audit.py --quiet https://vonc.com/index.html \
      https://dartsonline.com/index.html https://oufe.com/index.html
   vonc.com/index.html        contrast=33
   dartsonline.com/index.html contrast=13   h-overflow
   oufe.com/index.html        contrast=14
```

These are homepages only; fundamentallyai.com's 101 came from five pages, so the
per-site totals here are floors rather than totals. **dartsonline.com also scrolls
horizontally at 390px**, which is a separate defect this run happened to catch and
which is not otherwise filed.

Each of these sites is owned by another workstream. **Do not repaint them from here** —
`scripts/who-owns.py` first, then contribute the measurement into their thread. The
renderer fix repairs them the next time their stylesheet is rendered, which for most
of them will not happen on its own (`bugs_closed/072`: a stylesheet is written once).

> **A stylesheet is written once and never regenerated** (`bugs_closed/072`), so a
> site already carrying the defect keeps it until something rewrites its
> `styles.css`. That cuts both ways: the fleet is not silently repaired by the roll
> either. Each affected site needs a deliberate re-render.

## Fix

Shipped in `3096a55a6`, inert until the roll:

1. `fillDarkSchemeSpecialisedSlots` derives the missing slots from the core ones,
   contrast-picking each ink at AA against the fill it lands on. Inert unless the
   background is dark; never overwrites a slot the palette defines.
2. `paletteTextPreference` puts `text` ahead of `text_muted`; thresholds raised to
   WCAG AA (4.5 body / 3.0 heading); the `heading` slot is consulted first.
3. `warnUnusablePrimary` logs (b) rather than failing — unlike a scheme violation
   there is no single correct repair, because only the palette's author can decide
   whether primary is the brand's fill colour or its foreground colour.
4. Six tests, each proven load-bearing by defeating its own fix and watching only the
   matching test fail.

Council gate: correlation `f17b0a77-15e2-48ef-ba3e-9030ab4e0d8e`, three rounds.

| round | verdict | decided by |
|---|---|---|
| 1 | REVISE | gating objection from `bug_historian` |
| 2 | REVISE | **`unreadable reviewer(s): review_editquality.result`** |
| 3 | not submitted — round 2's remaining objections were all low-severity and are answered in code |

**Round 2 is worth reading carefully, because the verdict and the reviews say
different things.** Every seat that produced a readable review APPROVED — including
`bug_historian`, which had gated round 1, and `guardian`, `reuse_agent`, `guidelines`,
`tooling_provenance`, `improvement_guardian`, `render_guardian`, `debug_historian`,
`constitution`, `mission` and `prior_art_librarian`. The `revise` came from one seat's
output being unparseable, not from an objection. **There is therefore no APPROVED
verdict and no commit here carries a `Council-Reviewed:` trailer** — `unreadable: 1` is
exactly the field the trailer discipline says to check, and "everyone who spoke agreed"
is not the same as approval.

What round 1 changed in the code (the gating objection was right twice):
a derivation whose source slot is missing used to no-op silently into the same light
literal, and the derivation table patched an enumerated slot set while
`{{palette "X" "<literal>"}}` is generic. Both now warn; `warnLightLiteralsOnDarkSite`
reports the 60+ uncovered slot names rather than guessing values for them.

What round 2 changed: `bug_historian` and `guardian` independently noticed that the new
scanner recognises one spelling of the helper call and would silently report nothing on
any other — the same shape again, one level up. Verified that raw `{{palette`
occurrences equal strict matches in all 18 active layouts, then made the scanner compare
those two counts itself and warn on divergence, because the verification is a fact about
today.

## Ordering of the candidates — why the derivation comes first

The derivation makes the bad state **unrepresentable**: after it, a dark palette
cannot reach a template with a light card_bg, whatever anyone later writes into a
layout. The alternatives are all "someone must remember":

- *fix the 12 palettes' data* — repairs today's sites, leaves the 13th to be generated
  next week with the same shape;
- *change the layouts' literals to something neutral* — 18 layouts, hand-maintained,
  and the same drift class this council reviews for;
- *document that a palette must define 17 slots* — a schema defect in a documentation
  costume.

## What this is NOT

- Not `bugs_closed/022`. Same function, opposite half: 022 guards a core slot the spec
  *supplies*; this is about slots nobody supplies.
- Not `bugs_closed/072`. That is about component CSS snippets missing from a frozen
  stylesheet; this is about the variable values inside one.
- Not a claims or content defect: every word on the page is correct and grounded. It
  could not be read.
